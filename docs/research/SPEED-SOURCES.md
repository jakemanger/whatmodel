Integration details:

- speeds: published measurements, not predictions. Each includes source_id, immutable source URL, local evidence hash/row, full settings, and applicability restrictions. Do not collapse distinct context depths, precisions or execution providers. A repository commit pins the published result, not the downloaded model weights.
- findings: 22 Llama-3-8B-Instruct GGUF comparisons with an actual fp16 baseline, plus three DeepSeek-R1-Distill-Qwen-32B comparisons with a local BF16 baseline. The latter come directly from the CC BY 4.0 paper, not a license inferred from its harness. Percentages become fractions, and retention is recomputed without the backup’s three-decimal truncation. These are within-study observations; no universal quantization penalty table was rebuilt.
- quant_memory: Gemma 4 table 3 only. E2B/E4B use mobile mixed int2/int4 weights and int8 activations; 12B/26B-A4B/31B use Q4_0. The caption literally says Gb; source strings and MoE slash pairs are retained rather than silently asserted as GGUF file sizes or total runtime GB. No table 5/6 score extraction.
- calibration.measurements remains empty. Ten candidates retain verified tg32, parameter counts and GiB values, but lack a complete independently pinned bandwidth/active-parameter/hardware binding. Do not feed candidates into the old bandwidth fitter.
- api_speed_candidates are historical Groq/Llama 3.1 observations from a 2024 MIT-licensed committed CSV. Its fallback GPT-4 tokenizer differs from native Llama token counts, dates/model revisions are incomplete, and the current model routes are OpenRouter. They are explicitly ineligible for api.tps. No suitable current AA replacement was verified.

Material corrections and exclusions:

- The DGX Spark Qwen2.5-Coder-7B Q8_0 result is for the BASE checkpoint. The selected model is Instruct. Its old 29.43 tok/s row is excluded rather than transferred. M2 Ultra results also exclude that base checkpoint.
- ggml-org Qwen3-Coder Q8_0 and GLM-4.7-Flash Q8_0 do not support Q4_K_M speeds. GPT-OSS MXFP4 from ggml-org/llama.cpp does not automatically support an Ollama tag with the same quant name. Gemma 3 QAT Q4_0 is distinct from generic Q4_0/Q4_K_M. M2 Ultra core count and installed memory are not supplied by the benchmark document.
- ASR backup values were rounded and sometimes combined different execution providers. Exact English results distinguish CUDA, TensorRT, CPU int8, default precision and explicitly labeled fp16 cells. Unstated default precision is not assumed to be fp32. TensorRT fp16 enabling is not an assertion that every operation uses fp16. These timings do not describe NeMo, MLX or upstream Whisper.
- Apple SDXL results are Core ML, 1024×1024, 20 steps, end-to-end medians. They do not describe current diffusers CUDA commands or model-offload variants.
- Magpie CPU timings EXCLUDE load time. CPU q8_0 2.60 compute-seconds/audio-second becomes 0.384615×; this is a reciprocal of a rounded measurement, not extra precision. The GPU/Grace CPU paths are separate, and q8_0 retains a f32 codec.
- Chatterbox’s 0.499 RTF is from a streaming fork, not the selected upstream non-streaming engine. Its dtype is not stated. The reciprocal is explicitly marked.
- Wan PNG tables were visually inspected. H100/H800 and A100/A800 grouped source labels are preserved; we do not pretend to know which individual GPU was measured. CPU model offload is explicitly recorded and never labeled offload=none. All chosen values use the one-GPU column and T2V task.
- GLM-Image uses only batch-one T2I rows. Batch-four aggregate times are not treated as seconds per single image. Benchmark dtype is unstated rather than copied from unrelated example code.
- Llama-3-70B comparisons from matt-c1 have no fp16 run. Q5_K_M was previously put in full as a near-lossless proxy; those eight old retention rows remain excluded. Llama 3 is not Llama 3.1. The 8B study uses nonstandard test-set few-shot examples, skips ~20 overlength questions and lacks a fixed seed; those limitations accompany each finding.
- Full DeepSeek-R1/V3 comparisons in arXiv:2505.02390v1 are reusable CC BY evidence, but use FP8 API baselines. They were not restored into full-precision retention records. The three local BF16 32B rows were recovered.
- arXiv:2601.14277v1 declares the arXiv perpetual non-exclusive license, not a public CC reuse grant. Its values remain excluded under this audit’s explicit-grant standard.
- XiongjieDai/GPU-Benchmarks-on-LLM-Inference and miroleon/z-image-turbo-benchmark had no LICENSE/NOTICE file in their pinned trees. Do not infer permission from GitHub visibility.
- MFLUX’s README contains externally attributed user reports and approximate/bounded timings (for example <15s). The repo MIT grant alone does not verify the underlying reporters’ grant; these old measurements were not included.
- llama.cpp, geerlingguy, ik_llama and llamafile issue/discussion/PR-comment measurements were not licensed merely because their code repositories have a license.
- Unsloth website docs, third-party blogs, hosted leaderboard databases and sources not included in this narrow audit are not automatically forbidden; they remain unrecovered pending exact data and grant verification.
- MASSIVE-Agents ACL 2025.findings-emnlp.1099 Table 1 and all other Artificial Analysis derivative speeds are excluded. A paper’s CC grant does not establish a grant from AA for that third-party dataset.
