# Pass 10: unimported rows for catalogued models, Bielik rows, resolvable gaps (2026-10-10)

Candidates only; nothing in `data/` was edited. JSON: `docs/research/pass10-gaps-2026-10-10.json`. It has 114 results (109 independent, 5 lab), no new models or benchmarks, and 1 ledger `add_match`.

## Method

I re-read the pinned files of all 26 per-model ledger sources, 6,126 entries in all, and checked each entry against the notes of the rows already imported from that source. For entries that were not mapped yet, I looked for an exact catalogue match:

- **By Hugging Face repo.** This includes documented renames: `CohereForAI/*` became `CohereLabs/*`, `meta-llama/Meta-Llama-3.1-8B` became `Llama-3.1-8B`, and the root-namespace `gpt2` and `t5-*` became `openai-community/*` and `google-t5/*`.
- **By exact API id.**

For every source I also checked each catalogue model, benchmark by benchmark, against what the source publishes. Each row reuses the source's existing picking rule and note style:

- **Open PT:** source=hub, not flagged, bf16, fp16 or fp32, main revision.
- **EuroEval:** 5-shot accuracy, with one split per model. Zero-shot API runs are not imported (ledger attribution). Near-chance cells are held back, following the 2026-10-06 rule.
- **Polish EQ-Bench:** the latest unquantised `eq-bench_v2_pl` run for each model path.
- **StableLM:** the committed `evals/*.json` files.

## Caveats

- **The Open PT rows bring about 40 historical base models into the shared Open PT run.** These are OPT, Pythia, BLOOM, GPT-2, GPT-Neo and Llama 2 base. Most score near the random baseline (23-36 against 32.64). They were already partly bridged (pythia-2.8b-deduped, open-llama, phi-1 and gpt-1 are on the board). The 2026-10-06 import held EuroEval GPT-2 and Llama 2 rows over implausible placements. After merging, compare the top-5 and the leave-one-out error with the previous build. A full `node scripts/check.ts` (with the fit) in the copy ran 40 minutes without finishing and was stopped, so this pass has no leave-one-out or top-5 figures.
- **Phi-3-mini-4k EuroEval mapping.** The row maps to the June 2024 update because the cell was produced with EuroEval 15.10.1.dev0. That version falls between the PyPI releases on 2025-06-17 and 2025-06-20, a year after the repo's main revision moved to the update.
