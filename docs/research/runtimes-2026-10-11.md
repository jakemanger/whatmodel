## What changed or surprised

1. **llama.cpp's default port is now 9931, not 8080.** PR #30159 (merged 2026-10-09; nightly b11521 onward) made the change. The llama.app installer and winget ship b11540, which listens on `http://127.0.0.1:9931` (tested). Homebrew's stable 0.6.0 still uses 8080 and prints `notice: server default port will be changed to :9931 in a future release`. The llama.app docs pages still say 8080. The server always prints `listening on http://127.0.0.1:PORT`. To keep the URL predictable across versions, add `--port 9931`.
2. **llama.cpp `-hf` downloads now go to the Hugging Face cache** (`~/.cache/huggingface/hub/models--{owner}--{repo}`), not `~/Library/Caches/llama.cpp`. Tested on 0.6.0 and b11540. llama.app says models are "kept in the Hugging Face cache, shared with llama.cpp and other tools".
3. **llama.cpp without `:{quant}`** picks Q4_K_M, then Q8_0, then the first file. ggml-org repos often have no Q4_K_M, so `ggml-org/Qwen3.5-0.8B-GGUF` resolves to Q8_0 (834 MB). Ollama's `hf.co` with no tag picked the **BF16 (1.56 GB)** for the same repo. Always give a quant.
4. **Windows via winget has no `llama` command.** The winget package exposes `llama-server.exe`, `llama-cli.exe`, `llama-bench.exe` and so on, but no `llama.exe`. HF's snippet (`winget install llama.cpp` then `llama serve`) therefore fails there. Use `irm https://llama.app/install.ps1 | iex` (it installs `llama.exe`), or `llama-server -hf …` after winget.
5. **LM Studio `lms get` needs the full HF URL.** `lms get unsloth/Qwen3-0.6B-GGUF@Q4_K_M -y` fails with "Failed to resolve artifact … does not exist" because a bare `owner/name` is treated as an LM Studio Hub artifact. `lms get https://huggingface.co/unsloth/Qwen3-0.6B-GGUF@Q4_K_M -y` works. The downloaded model gets a derived key (`qwen3-0.6b`, the same key for the GGUF and the MLX build), and `lms load <repo id>` fails. The site has to say "run `lms ls`, then use that key", or use `lms load` without `-y` to get a picker. `lms` only works after the app has been opened once. Before that it errors: "LM Studio daemon is not running and no valid installation could be found".
6. **MLX-LM serves on 8080 with no web UI** (`GET /` returns 404). HF's MLX snippet curls `localhost:8000`, which is wrong. Port 8080 also clashes with Homebrew llama.cpp's current default.
7. **huggingface_hub 2.2 (pulled in by mlx-lm 0.32) uses a shared blob store** at `~/.cache/huggingface/hub/blobs`, so deleting a `models--*` folder does not free the space. Use `hf cache rm model/{repo}`. `hf cache prune` also deletes other "unreferenced" repos (its dry run listed a pre-existing kyutai repo here).
