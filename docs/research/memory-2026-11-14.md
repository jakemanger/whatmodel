# Memory audit, 14 November 2026

## What was wrong

- 3,725 local downloads had a size, but almost all were estimates: parameters × bytes per weight × 1.2 + 0.5 GB.
  The estimate assumed a "1-bit" download takes 1 bit a weight. Unsloth's dynamic 1-bit GGUFs take about
  2.2, so every large model's 1-bit download was listed at about half its size: Kimi K2 at 150 GB (really
  280 GB), GLM-4.7 at 54 GB (97 GB), Qwen3.5 397B at 60 GB (108 GB), Llama 4 Maverick at 61 GB (123 GB). The
  board then offered those models to machines that can't hold them.
- The precision parser read any name it didn't know as 4-bit: fp32, fp8, int8, NVFP4 and others were shown
  as "4-bit".
- Some precision names didn't match their files: A.X-K2, Mistral Large 4 and DeepSeek-TNG R1T2 Chimera were
  "bf16" but are FP8 checkpoints; DeepSeek-V4-Flash-Vision-Exp's FP8 repo holds FP4 experts.
- Machine memory was compared in the wrong units: cards and RAM are sold in binary gigabytes (24 GiB = 25.77
  billion bytes), downloads are listed in billions of bytes.
- System RAM for a spilled model was counted as 80% of (RAM − 4 GB), which ruled out runs people make every day
  (gpt-oss-120b on a 16 GB card with 64 GB of RAM).

## What changed

- `npm run sizes` sums the files each command downloads from the host's own listing (Hugging Face API at a
  pinned commit, Ollama registry manifest), including split GGUF parts, the vision projector llama.cpp and
  Ollama load, `-hff` files and pinned revisions. 3,107 downloads are measured; 19 without a readable listing
  are re-estimated from measured bits per weight per format (lib/quant.ts `bitsPerWeight`).
- `npm run check` fails on a size outside its precision's range, an unknown precision name, or `needs`
  that can't hold the download (lib/memory.ts). A measured size that is real but unusual (Gemma 3n's
  per-layer embeddings) must carry a `size_note`.
- Machine memory is converted to download units; spilled models may use all RAM but 8 GB.

## Evidence the rules are checked against (tests/memory.test.ts)

- Every speed measurement recorded as running entirely on a known GPU (73 runs) must fit that GPU.
- Published reports of one download on one machine, collected 14 November 2026. Each must come out the way it
  did: entirely on the GPU, partly in RAM, or not at all.

## Not measured

- Strata's split downloads: their GPU memory and RAM come from Strata's own setup.py and README.
- Five repos that need a Hugging Face login, four GGUF repos whose files don't follow their tags, one command
  that names no download, and one installer that fetches its own files. Their sizes stay estimates (marked ~).
